# 材料与活文档模式

用既有材料约束追问，减少重复提问和无依据推断。材料可以是代码、项目文档、研究笔记、论文、数据字典、引文、访谈记录、规范或决策记录。

## 选择写入级别

- **只读核对**：默认级别。读取和引用材料，指出冲突，不改写文件。
- **活文档维护**：用户明确要求维护、同步、补充或依据文档持续记录时启用。每批答案收敛后立即写回已经确定的内容，不等整个访谈结束。

材料存在不等于获得写入授权。开始时用一句话说明当前级别。

## 处理顺序

1. 识别与当前问题直接相关的材料，只读取必要部分。
2. 标记材料中的事实、定义、既有决定、证据和未决问题。
3. 检查材料之间以及材料与用户陈述之间的冲突。
4. 能由材料回答的问题直接给出结论和出处；只把真正需要判断、取舍或补充的信息问给用户。
5. 材料不足时明确区分“未提供”“材料相互矛盾”“可以合理推断”和“无法判断”。
6. 活文档维护时，只写回本批已锁定的事实、术语或决定；保留未决项，不替用户补齐共识。

## 各路由关注点

- **工程**：代码行为、接口、配置、测试、`CONTEXT.md`、ADR 与实际部署约束是否一致。领域语言按 [context-docs.md](context-docs.md) 处理，架构决定按 [adr-docs.md](adr-docs.md) 处理。
- **科研**：原始文献、研究笔记、数据说明、代码本、分析代码与研究主张是否一致。
- **决策**：时间、资源、承诺、规则等可核实事实与个人预测是否混在一起。
- **思辨**：原话、上下文、转述链和解释是否被混为一谈。

写回后重新读取相关片段，确认标准术语、代码事实、决定理由与本轮结论一致。最终输出列出本次更新的文件；只读核对则列出发现的冲突与待处理项。
